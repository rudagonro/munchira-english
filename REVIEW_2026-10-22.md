# Revisión de NIVelo — 22 de octubre de 2026

## Alcance y resultado

Revisión estática del frontend, configuración, dependencias, banco de preguntas, reglas de progreso y documentos locales. El repositorio remoto contenía únicamente su README inicial; esta entrega incorpora el proyecto local conservando ese historial. Se mantiene React + Vite + React Router + Supabase.

La aplicación contiene acceso por correo/Google, perfil por rol, diagnóstico adaptativo, consulta de ciclos, desbloqueo secuencial, flashcards, lecciones, audio por diálogo, quizzes y checkpoints. El panel docente sigue siendo un placeholder. No se implementaron las funcionalidades grandes del roadmap ni se incorporó código de otros proyectos.

## Correcciones incluidas

- ESLint: corregidos los 10 errores y las 3 advertencias iniciales; separado el contexto de autenticación de su hook y estabilizadas las consultas usadas en efectos.
- Sesión: limpieza de suscripciones y protección contra respuestas de perfiles obsoletas; solicitudes de perfil diferidas fuera del callback de autenticación; salida de carga ante fallos de sesión.
- Acceso: la ruta de login conserva el destino solicitado. La vista de módulo comprueba pertenencia al ciclo activo y disponibilidad antes de cargar contenido. Esta comprobación es de interfaz y no reemplaza autorización en servidor.
- Módulos: reinicio de estado al cambiar de módulo, mensajes para módulos sin contenido o quiz, reinicio de ejercicios por lección y comprobación de errores al guardar checkpoints y avanzar de ciclo.
- Diagnóstico: búsqueda acotada de preguntas para evitar recursión infinita cuando se agotan bancos adyacentes; dependencia de nivel corregida.
- Flashcards: corregida la cola que reinsertaba tarjetas ya dominadas después de marcar para repaso la última tarjeta de una ronda.
- Audio: texto nulo tolerado, errores de reproducción gestionados, reproducción previa detenida y URLs temporales liberadas al cambiar de lección o salir.
- Progresión: la felicitación por ciclo completo ahora exige aprobar todos sus checkpoints.
- Dependencias: actualizaciones compatibles mediante npm, sin `--force`; auditoría final con cero avisos conocidos en ese momento.
- Entrega: README actualizado, variables de ejemplo sin valores de un proyecto real, exclusión de `.env`, configuración local y descargas de referencia; CI y reescritura de rutas para Vercel; idioma HTML español.

## Validación

- `npm run lint`: pasa sin errores ni advertencias.
- `npm test`: pasan 5 pruebas, incluyendo bloqueo por checkpoint, aprobación histórica, finalización del ciclo, agotamiento completo sin repetir preguntas y coherencia de las opciones del banco.
- `npm run build`: compilación de producción correcta.
- `npm audit`: cero vulnerabilidades después de actualizar dependencias.

Las pruebas automatizadas cubren lógica pura. No se ejecutó una sesión autenticada de estudiante o docente ni una validación visual en navegador. No se verificaron Google OAuth, envío de correo, reproducción TTS real, datos de cursos ni escrituras en Supabase. La compilación no demuestra que esos servicios estén configurados.
